# HTML → PPTX для GigaCode

Проект подготавливает существующий HTML со слайдами `section.slide` к экспорту в PowerPoint. Композицию рассчитывает обычный браузер, а включённая библиотека dom-to-pptx 2.1.2 переносит элементы в PPTX по их фактическим координатам. GigaCode не проектирует слайды заново.

**Один ручной шаг обязателен:** открыть подготовленный HTML и нажать «Скачать PPTX». DevTools, remote debugging, CDP, Playwright и браузерный сервер в рабочем процессе не используются.

## Быстрый запуск

Распакуйте проект. Папка `.gigacode` скрытая: не пропустите её при переносе. На рабочей машине нужны Python 3.9+ и обычный современный браузер Chromium, в котором разрешены локальные JavaScript и скачивание файлов. Новое ПО во время работы не скачивается. Перенос включённого стороннего JS должен соответствовать правилам вашей организации.

Перейдите в папку проекта, запустите GigaCode привычным способом и дайте запрос:

> Прочитай .gigacode/skills/html-to-pptx/SKILL.md. Подготовь /полный/путь/deck.html к экспорту в PPTX. Сохрани исходную структуру и оформление. Результат подготовки запиши рядом под новым именем deck-export.html. Не устанавливай ничего и не используй remote debugging.

Если ваш GigaCode уже автоматически обнаруживает скиллы, достаточно обычного запроса на конвертацию. Явное указание SKILL.md работает как инструкция даже при другом механизме обнаружения скиллов. Проект не меняет настройки GigaCode.

Для подключения к существующему проекту перенесите каталог `.gigacode/skills/html-to-pptx` целиком. Не перезаписывайте чужой `GIGACODE.md`.

В `examples/demo-export.html` уже подготовлен автономный пример: его можно сразу открыть и проверить кнопку экспорта. Рядом лежат исходный `demo.html` и полученный `demo.pptx`.

## Запуск без агента

Из корня проекта:

```bash
python3 .gigacode/skills/html-to-pptx/scripts/prepare.py examples/demo.html -o demo-export.html
```

Откройте `demo-export.html` двойным щелчком. Проверьте, что в окне правильно отображаются оба слайда. При необходимости измените ширину/высоту окна и нажмите «Применить». Затем нажмите «Скачать PPTX». Найдите `demo.pptx` в загрузках браузера и откройте в PowerPoint.

Для своего файла:

```bash
python3 .gigacode/skills/html-to-pptx/scripts/prepare.py "/путь/deck.html" -o "/путь/deck-export.html"
```

Если картинки или CSS лежат в общей родительской папке:

```bash
python3 .gigacode/skills/html-to-pptx/scripts/prepare.py "/проект/slides/deck.html" -o "/проект/deck-export.html" --resource-root "/проект"
```

В Windows вместо `python3` может использоваться `python` или `py -3`.

## Версия 1.2: разные блоки накладываются только в PPTX

Устранён режим автоматического увеличения текстовых рамок (`spAutoFit`). Он позволял PowerPoint увеличить рамку и зайти на соседний объект, координаты которого оставались фиксированными. Теперь для отдельных текстовых объектов используется подгонка текста внутри измеренной рамки (`normAutofit`, `fit=shrink`), без автоматического роста фигуры.

Дополнительно для отдельно измеренных текстовых узлов убраны повторно добавляемые внешние отступы родителя: их положение уже учтено браузером.

После обновления заново подготовьте `*-export.html` и сначала экспортируйте при **100%**. Регулировка 95/90% остаётся резервным способом коррекции. Поведение подгонки зависит от просмотрщика; `normAutofit` не гарантирует одинаковый перерасчёт при первом открытии во всех версиях PowerPoint. Если текст продолжает выходить за рамки, настройка масштаба остаётся полезной. Нативные таблицы используют отдельный алгоритм: этот патч не является исправлением любой возможной проблемы высоты таблицы.

Точная причина корпоративного дефекта не подтверждена без файла. Исправлен конкретный механизм, который мог приводить к описанному поведению. Проверена структура PPTX, а не отображение в Microsoft PowerPoint.

## Настройки окна и размера текста

Высота HTML-окна управляет viewport браузера, а не высотой фиксированного `section.slide`. Поэтому её изменение может не влиять на PPTX. Параметры окна теперь применяются и при нажатии экспорта.

Добавлен независимый параметр **«Текст в PPTX, %»**. По умолчанию 100% сохраняет прежний размер. При наложении текста в PowerPoint попробуйте 95%, затем 90%. Он изменяет размеры редактируемого текста и абсолютный межстрочный интервал после измерения HTML. Позиции и размеры объектов остаются прежними. Предпросмотр продолжает показывать оригинальный HTML. Для проверки результата нужно заново скачать PPTX.

Настройка не исправляет пересечение самих объектов, наложения уже в исходном HTML или текст, который экспортирован изображением. Она не гарантирует отсутствия наложений на любом HTML. Не уменьшайте весь слайд ради одного дефектного блока без проверки читаемости.

После обновления проекта обязательно **заново запустите prepare.py для исходного HTML**, выбрав новое выходное имя. Ранее подготовленные `*-export.html` содержат старую встроенную библиотеку и сами не обновляются.

## Что сохраняется

- Один исходный `section.slide` соответствует одному слайду PPTX, порядок сохраняется.
- Координаты, размеры, сетки/колонки определяет браузер по исходному CSS. Нет LLM-переразметки, пересказа или добавления титульного слайда.
- Текст и многие фигуры остаются редактируемыми. Изображения остаются изображениями.
- Таблицы могут быть набором редактируемых текстов/фигур, а не одним объектом таблицы PowerPoint.
- Для единого формата PPTX берётся максимальная ширина и высота слайдов. При разных пропорциях добавляются поля, содержимое не растягивается непропорционально.
- Сложные эффекты поддерживаются в пределах возможностей dom-to-pptx. Полной пиксельной идентичности нет, произвольный неподдерживаемый элемент автоматически в скриншот не превращается.

## Поддерживаемый вход и ограничения

Вход: статический HTML в UTF-8, встроенные или локальные CSS, локальные/встроенные изображения. Относительные пути разрешаются относительно HTML или соответствующего CSS. Простые CSS `@import` включаются рекурсивно. CSS с экзотическими экранированными URL или импортами с `layer()`/`supports()` не входит в проверенный набор.

Удаляются исходные JavaScript, обработчики событий, iframe/object/embed и служебные ссылки. Об этом сообщаются предупреждения. Поэтому графики Plotly/Chart.js, контент, который создаётся JS, внешние виджеты и canvas нельзя конвертировать этим путём без предварительного статического представления. Удаление скрипта не доказывает, что он был не нужен: обязательно сверяйте предпросмотр с оригиналом.

Внешние картинки/CSS требуют локальных копий; конвертер сам их не загружает. `srcset`, `<base>`, скрытые слайды, вложенные `section.slide` и трансформации корня не поддерживаются. При переполнении корневой рамки экспорт останавливается, чтобы не скрыть обрезание. Для `height:auto` используется фактически измеренная высота.

Шрифты не встраиваются в PPTX автоматически. Локальный web-font может отображаться в HTML, но отсутствовать в PowerPoint. Для устойчивого результата используйте шрифты, установленные на машине просмотра PPTX. Рекомендуется проверить кириллицу и переносы строк.

Исходные внешние гиперссылки могут сохраниться как ссылки; конвертер их не открывает. Не нажимайте их, если нужен строго офлайн-просмотр.

Подготовленный HTML содержит все исходные данные. JSON-отчёт содержит текст слайдов. Храните их по тем же правилам, что исходный корпоративный документ.

## Проверка

После скачивания PPTX:

```bash
python3 .gigacode/skills/html-to-pptx/scripts/validate_pptx.py "/путь/deck.pptx" --expected-slides 2
```

Проверяются целостность ZIP, XML, количество слайдов и наличие текстовых объектов. Это не визуальная проверка PowerPoint.

Автотесты подготовки без дополнительных зависимостей:

```bash
python3 -m unittest discover -s tests -v
```

В `tests/TEST_RESULTS.md` указаны реально выполненные проверки и их пределы. Браузерный тест предназначен только для среды разработки с уже доступными Playwright и Chromium; они не входят в требования проекта и не нужны на корпоративном компьютере.

## Ошибки

- `DevTools remote debugging is disallowed...`: этот проект не запускает remote debugging. Если сообщение возникает, проверьте, что агент запускает именно `prepare.py`, а не сторонний CLI-конвертер.
- Нет кнопки или библиотека не загрузилась: возможно, политиками запрещены локальные скрипты. Проект не меняет эти политики.
- Браузер не скачивает: проверьте обычный интерфейс загрузок/сообщение блокировки; не отключайте защиту.
- «Внешний ресурс запрещён»: поместите разрешённую локальную копию рядом и исправьте путь в копии HTML.
- «Выходной файл уже существует»: выберите новое имя. Исходники и предыдущие результаты не перезаписываются.
- Отличается вёрстка: сначала сопоставьте ширину/высоту окна предпросмотра с оригиналом. Если HTML выглядит верно, а PPTX нет, это ограничение переноса; не просите агента молча переделать слайд.

## Состав

`GIGACODE.md` — инструкция проекту. `.gigacode/skills/html-to-pptx/` — переносимый скилл, два Python-скрипта, HTML/JS интерфейс и локальная браузерная библиотека. `examples/` — синтетический пример. `tests/` — проверки и результаты.

Источник библиотеки: https://github.com/atharva9167j/dom-to-pptx . Версия и SHA-256: `assets/vendor/manifest.json`. Исходная лицензия и дополнительные уведомления включены. В версии 1.2 браузерная сборка содержит локальные патчи: масштабирование текстовых метрик, запрет роста текстовых рамок (autoFit выключен, fit=shrink), исключение повторного переноса внешних отступов родителя в отдельно измеренные текстовые узлы. Исходная и текущая SHA-256 записаны в manifest.json. Design-Arena/html-to-pptx использован как архитектурный референс, его код не включён.
